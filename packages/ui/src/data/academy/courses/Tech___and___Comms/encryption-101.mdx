# 🔐 Encryption 101
<TrackBadge variant="default" />

<Callout type="info">
End-to-end encryption (E2EE) is one of the **strongest shields against surveillance**. This guide shows how it works, when to use it, and how to avoid common mistakes.
</Callout>

---

## 🧠 Why It Matters

Encryption protects people’s stories, evidence, and movements.  
Used correctly, it prevents **over 99% of mass surveillance intrusions**.  
Used carelessly, it provides false confidence and dangerous leaks.

<Callout type="hint">
Pair encryption with **data ethics** and **retention hygiene**.  
See <a href="/courses/data-ethics-pledge">Data Ethics Pledge</a>, <a href="/courses/digital-security-basics">Digital Security Basics</a>, and <a href="/courses/after-action-data-hygiene">After-Action Data Hygiene</a>.
</Callout>

## 🧩 What Is Encryption?

Encryption scrambles readable data so only those with the correct key can restore it.

> Think of it as placing a message in a locked safe.  
> Without the combination, even if someone steals it, they can’t open it.

| Without Encryption | With Encryption |
|--------------------|----------------|
| Readable by anyone | Locked with a mathematical key |
| Easy to intercept | Nearly impossible to decrypt |
| Leaks contents & identities | Protects contents (but not who or when) |

<Callout type="warning">
Encryption protects **content**, not **metadata**.  
Who sent it, when, and from where may still be visible.
</Callout>

---

## 🔑 End-to-End Encryption (E2EE)

**End-to-End** means only the sender and receiver hold the keys.  
No one else—including ART, app servers, or governments—can read the data.

### Simplified Flow
1. You write a report.  
2. Your passphrase + salt generate a **secret key**.  
3. That key encrypts the data before upload.  
4. The server stores only ciphertext.  
5. The recipient decrypts locally using the same key.

<Callout type="info">
ART’s encryption uses **audited, modern cryptography**.  
The passphrase is never stored—**lose it and the data is unrecoverable.**
</Callout>

---

## 🧮 Core Terms

| Term | Meaning |
|------|----------|
| **Encryption** | Converts readable data into coded form |
| **Decryption** | Restores coded data to readable form |
| **Passphrase** | A personal key to unlock encrypted data |
| **Salt** | Random data preventing predictable keys |
| **Metadata** | Info about the message (who, when, where) |
| **Brute-Force Attack** | Rapid guessing of possible keys |
| **Forward Secrecy** | Every report uses a unique key, limiting exposure |

---

## 🔐 How ART Implements Encryption

- Optional passphrase protection for dispatches.  
- Passphrases **never leave the user’s device**.  
- Data is locked using **AES-GCM or libsodium-based ciphers**.  
- Only those with the correct passphrase can decrypt it.

<Callout type="warning">
🛑 **Lose the passphrase = permanent loss.**  
ART cannot reset or recover encrypted content.  
Write it down securely or memorize it.
</Callout>

---

## 🧱 Strong Passphrases

✅ **Do**
- Use **5+ random words**: `crane-mango-cloud-echo-harbor`  
- Generate from diceware or password manager  
- Change after high-risk missions  

❌ **Avoid**
- Short or reused passwords  
- Birthdays, names, or jokes  
- Anything you’ve typed elsewhere  

---

## 🔄 Sharing Passphrases Safely

| Safe | Unsafe |
|------|---------|
| Signal (voice or direct message) | Email or SMS |
| In-person exchange | Shared docs or public chats |
| Handwritten note in sealed envelope | Group threads or screenshots |

<Callout type="hint">
Prefer **Signal voice call** or **in-person**.  
Never reuse passphrases between reports.
</Callout>

---

## 🧰 When to Encrypt

Use encryption when data includes:
- Personal or identifying info  
- Legal or immigration status  
- Surveillance targets or safe-house locations  
- Minor or family details  

Skip encryption for:
- Public info or press releases  
- Low-risk, time-critical updates  

<Callout type="info">
Partial encryption works: redact only sensitive parts and leave general context open.
</Callout>

---

## ⚙️ Hybrid Encryption Example

Some messages contain public and private sections:  
**Public:** “Supply drop completed at Hilltop Park.”  
**Encrypted:** Coordinates, license plates, shelter name.  

This limits exposure while maintaining situational awareness.

---

## 🧪 Try It: Shelter Report Exercise

Scenario: ICE raid **outside** a known shelter.

1. Encrypt the **shelter name and address**.  
2. Leave public location context visible.  
3. Share the passphrase **via Signal voice**.  
4. Rotate the passphrase after debrief.  

If the passphrase was leaked:  
- Assume compromised.  
- Notify dispatch immediately.  
- Submit a new encrypted report with new key.
