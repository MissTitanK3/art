# 📡 Comms Collapse Scenarios & Offline Protocols
<TrackBadge variant="default" />

<Callout type="warning">
🛰️ When Signal fails, networks go dark, or surveillance spikes, what keeps you connected?  
This course teaches **layered fallback protocols** so your pod stays operational even when digital infrastructure collapses.

## 🧠 Why This Matters

Modern networks are fragile:
- Governments can **cut mobile service or throttle data**.  
- Protest zones often face **localized blackouts or jamming**.  
- **IMSI catchers and routers** can fake trusted networks.  
- “Safe apps” can become **surveillance traps overnight**.

Prepared pods treat collapse as **an operational phase**, not a surprise.

## 🔁 The Collapse Playbook

### 🧩 1. Build Redundancy Beforehand

- Use **two or more comm paths** per pod (Signal + radio + runner).  
- Print **pod lists and fallback maps** on water-resistant paper.  
- Designate **offline rally sites** and “dead drop” locations.  
- Assign a **collapse lead** responsible for protocols.

<Callout type="hint">
Coordinate with <a href="/courses/runners-and-rides">Runners & Rides</a> and <a href="/courses/responding-to-dispatch-calls">Responding to Dispatch Calls</a>.
</Callout>

---

### 🕒 2. Offline Rendezvous System

| Element | Function |
|----------|-----------|
| Time slots | “If comms fail, meet at 09:00 / 12:00 / 16:00” |
| Fallback sites | Safe cafes, community centers, aid hubs |
| Rotation windows | Shift check-ins by daylight cues |
| Paper boards | Post updates anonymously (no names) |

<Callout type="info">
Follow <a href="/courses/documentation-safety">Documentation Safety</a> and <a href="/courses/after-action-data-hygiene">After-Action Data Hygiene</a> for all printed materials.
</Callout>

### 🧍 3. Human Runners

- Walk, bike, or drive updates between pods.  
- No identifiers, devices, or branded gear.  
- Carry updates on small coded slips.  
- Confirm delivery **verbally or via mark** (e.g., chalk line).  
- Use **pre-agreed code phrases** only.  

> Example: “Grandma’s soup was delivered” = safe site confirmed.

---

### 📻 4. Radios and Mesh Tools

| Tool | Range | Risk |
|------|--------|------|
| FRS/GMRS | Short range | Public, no encryption |
| Baofeng (VHF/UHF) | City-wide | Legal restrictions apply |
| LoRa (Meshtastic) | Multi-pod mesh | Encrypted, slow, resilient |

<Callout type="warning">
Radio is **always public unless both ends are secured**.  
Avoid personal details, names, or exact coordinates.
</Callout>

<Callout type="info">
Meshtastic and similar LoRa tools allow **slow syncs** of dispatch data between pods without internet.
</Callout>

## 🔐 Offline Security Habits

| Practice | Why |
|----------|------|
| Code language | Conceals sensitive info in casual phrases |
| Chalk or tape markers | Signal zone status discreetly |
| Paper alerts | Spread info door-to-door fast |
| Silence periods | Reduce surveillance pattern matching |
| Rotation of codebooks | Prevent leaks from old phrases |

<Callout type="hint">
Keep language **mundane** and **repeatable**. Avoid “activist code words.”
</Callout>

## 🧪 Practice Drill

**Collapse Simulation**

1. Turn off all internet and phones.  
2. Assign a test event (e.g., ICE sighting).  
3. Deliver info via printed slips or runners.  
4. Track delivery time and confusion points.  
5. Debrief and update protocol.

<Callout type="success">
Run this drill **quarterly**. Update fallback maps and code lists after each test.
</Callout>

## 🧭 Psychological Readiness

- Expect confusion. Calm is your advantage.  
- Assign “anchor” roles: people who stabilize morale.  
- Treat collapse as **temporary silence, not failure**.  
- Keep fallback updates brief and factual.  

---

## 🪧 Countering Misinformation

During collapse, false updates spread fast.  
- Verify through **two independent sources** minimum.  
- Never post unverified warnings in fallback zones.  
- Use **colored or signed flyers** to mark authenticity.
