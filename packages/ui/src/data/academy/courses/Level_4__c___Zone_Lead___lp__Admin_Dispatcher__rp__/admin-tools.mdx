# 🔐 Admin Tools and Oversight
<TrackBadge variant="pod-leadership" />

<Callout type="info">
Admin-level dispatchers maintain the backbone of ART’s trust network.  
This course teaches how to manage tools responsibly, support teams, and preserve ethical transparency at every layer.
</Callout>

---

## Overview

Level 4 Admins balance coordination power with data sensitivity.  
You can create dispatches, manage roles, record trust signatures, and review activity — but **every click carries ethical weight**.  
This module clarifies what admins can and can’t do, and how to act as *stewards*, not owners.

---

## Learn & Do

### Core Admin Permissions (Today)

Admins **can**:
- ✅ Create or edit dispatches  
- 🔐 Adjust user access roles (promote/demote)  
- 🤝 Record **trust signatures** documenting vouches  
- 🧭 Assign coordination zones and coverage  
- 📋 Review, approve, or remove reports (if region-enabled)  
- 🕓 Review recent activity logs

Admins **cannot yet**:
- ⛔ View full audit logs in-app (use server logs)  
- ⛔ Export full CSVs (request limited server export)  
- ⛔ Draw map geofences (use labels instead)

<Callout type="warning">
Tool capability ≠ moral authority.  
Use minimal privilege. Escalate uncertain decisions for review.
</Callout>

---

### Creating & Editing Dispatches

Manual creation bypasses normal triage and should be rare.

**Use only when:**
- Verified urgent event (raid, medical, imminent threat)  
- Requested by another dispatcher  
- Confirmed trusted intel  

**Guidelines:**
- Log accurate location and time  
- Mark urgency and audience clearly  
- Add internal notes for trusted roles  
- Follow up after closure for accountability  

<Callout type="important">
Manual dispatch is an exception, not convenience.
</Callout>

---

### Access Roles & Trust Signatures

**Roles**  
- Dispatcher → base field coordination  
- Verified Dispatcher → can assign and coordinate  
- Admin Dispatcher → full oversight + tools  

**Trust Signatures**  
Document *who vouched for whom*, not automatic promotion.  
Promotions require regional prerequisites (training, referrals, review).

**Best practice:**  
Record reason for every change, e.g.  
> “Certified + consistent field leadership.”

<Callout type="warning">
Never promote from friendship or pressure.  
Trust is collective currency — spend it slowly.
</Callout>

---

### Coordinating Coverage (Labels > Geofences)

Use **labels and assignments**, not drawn zones.  

- 🌐 Label coordination areas (“Tacoma West Zone”)  
- 📍 Assign temporary event coverage  
- 🧭 Track shifts in scheduling tools  
- 💬 Add language or accessibility tags  

Avoid overlap. Assign one lead and one backup.  
Maintain quiet hours and escalation paths.

---

### Report Review & Removal

Admins can validate or reject reports. Always document reasoning.

**Do:**
- Approve only verified info  
- Log rejections with short rationale  
- Escalate contested removals to accountability team  

**Don’t:**
- Delete without trace  
- Resolve conflicts privately  

Transparency sustains credibility.

---

### Activity Review & Audits

From admin dashboard or server logs, you can:
- Review recent role and dispatch changes  
- Conduct monthly response audits  
- Request redacted exports for analysis  

<Callout type="warning">
Exports can be subpoenaed.  
Never include names, addresses, or identifiers. Aggregate when possible.
</Callout>

---

### Compromised Accounts Protocol

1. Revoke access immediately  
2. Notify core team and region leads  
3. Audit recent actions  
4. Reset credentials  
5. File a short incident note in the **Admin SOS** Signal channel  

Speed and transparency prevent secondary harm.

---

### Accountability Standards

Admins are **stewards**, not bosses.  
You are responsible for safety, documentation, and cultural tone.

- Edit only for clarity or emergency corrections  
- Never alter reports to fit narrative  
- Attend monthly admin syncs  
- Submit bug or friction reports via [/admin-feedback](/admin-feedback)

<Callout type="info">
Authority in ART is rotational and reviewable.  
If you can’t explain a decision publicly, rethink it.
</Callout>
